# 036. Multiplication Without the Multiply Operator

## Difficulty: Hard

## Problem Statement

Implement integer multiplication of two `int32_t` values using **only bitwise operations and your own addition function** — no `*`, `/`, or `%` operators allowed. You may use `+` (or preferably, implement addition with XOR/carry as in problem 035).

The approach is the **Russian Peasant Algorithm** (also called "shift-and-add" or "binary multiplication"): for each set bit in the multiplier, shift the multiplicand left by that bit position and accumulate. This is exactly how hardware multipliers work.

## ⚠️ Critical Embedded Pitfalls (Senior-Level Differentiators)

### 1. O(n²) vs O(n) Complexity Trap

This multiplication algorithm iterates through all 32 bits of the multiplier. For each bit, it performs a shift (O(1)) and an add (O(n) if using bitwise addition from Q035). Total: **O(n²)** where n=32 — compared to O(n) for hardware multiply.

In firmware, this matters:
- **8-bit MCUs without MUL instruction** (PIC10, ATtiny) use exactly this algorithm
- **Software multiply for 64-bit on 32-bit ARM** uses this pattern (pair of 32-bit multiplies + shifts)
- **Critical path analysis**: A tight ISR doing sensor calibration via `value * scale_factor` becomes 32× slower without hardware multiply

### 2. Signed Multiplication: Convert to Unsigned, Multiply, Restore Sign

The safest approach for signed multiplication:
1. Record the sign: `negative = (a < 0) ^ (b < 0)`
2. Convert both to positive (absolute value) — but **beware abs(INT_MIN) is UB!**
3. Multiply the unsigned magnitudes
4. Negate the result if needed

**INT_MIN trap**: `abs(-2147483648)` cannot be represented as a positive `int32_t`. You must use `uint32_t` for the magnitude or handle INT_MIN as a special case.

### 3. Overflow Semantics: Wrapping is Correct

Like hardware multiplication, the lower 32 bits of the product are returned. This means:
- `INT_MAX * 2` wraps (same as hardware MUL instruction)
- The result matches what `(int32_t)(a * b)` would give (modular arithmetic)
- No overflow detection is required — this is the expected behavior for embedded register-width multiplication

### 4. Shift-and-Add is the Hardware Multiplier

A Booth's multiplier or array multiplier in silicon does exactly this:
- Partial products are generated by ANDing the multiplicand with each multiplier bit
- Partial products are shifted to the correct position
- All partial products are summed (using carry-save adders in hardware, or sequential addition in software)

Understanding this helps when:
- Debugging DSP code on MCUs without hardware MAC
- Verifying silicon multiplier behavior during bring-up
- Optimizing by choosing "multiply by constant" via shifts (e.g., `x*10 = (x<<3) + (x<<1)`)

### 5. Qualcomm Follow-Up: "Use your add() function"

A classic Qualcomm/Nvidia interview pattern: implement `add()` first (Q035), then use it inside `multiply()` — demonstrating that you can build arithmetic from pure bitwise ops. No `+` operator at all.

## Function Signature
```c
int32_t multiply(int32_t a, int32_t b);
```

## Parameters
| Parameter | Type      | Description            |
|-----------|-----------|------------------------|
| `a`       | `int32_t` | Multiplicand           |
| `b`       | `int32_t` | Multiplier             |

## Return Value
Return the product `a * b` (lower 32 bits), computed without using `*`, `/`, or `%`.

## Examples

### Example 1
```
Input:  a = 6, b = 7
Output: 42
Explanation: 7 in binary = 0111.
             Bit 0 set: accumulate 6 << 0 = 6
             Bit 1 set: accumulate 6 << 1 = 12
             Bit 2 set: accumulate 6 << 2 = 24
             Total = 6 + 12 + 24 = 42
```

### Example 2
```
Input:  a = -3, b = 4
Output: -12
Explanation: sign = negative (signs differ).
             |a|=3, |b|=4. Multiply: 3*4=12. Negate: -12.
```

### Example 3
```
Input:  a = -7, b = -6
Output: 42
Explanation: sign = positive (both negative). |a|=7, |b|=6. 7*6=42.
```

### Example 4
```
Input:  a = INT_MIN (-2147483648), b = 1
Output: -2147483648
Explanation: Multiplying by 1 returns the same value. Must handle INT_MIN correctly.
```

### Example 5
```
Input:  a = 65536, b = 65536
Output: 0
Explanation: 65536 * 65536 = 2^32 = 0 (wraps in 32-bit). Lower 32 bits are all zero.
```

## Constraints
- `a` and `b` are any valid `int32_t` values (including INT_MIN, INT_MAX, negative, zero)
- You must NOT use `*`, `/`, or `%` operators
- You MAY use `+` (or implement addition with bitwise ops for full marks)
- The result wraps on overflow (lower 32 bits of the mathematical product)

## Notes

### Interview Follow-Up Questions:
1. **"What's the time complexity?"** → O(32) iterations × O(1) shift+add = O(n) if using `+`. But O(n²) if addition itself is bitwise O(n).
2. **"What happens with INT_MIN * -1?"** → Mathematically = +2147483648, which overflows int32_t. Result wraps to INT_MIN (same as hardware). Your code must not crash.
3. **"Can you optimize multiplication by a known constant?"** → Yes: `x*10 = (x<<3)+(x<<1)`, `x*7 = (x<<3)-x`. Compilers do this automatically.
4. **"How does this differ from Booth's algorithm?"** → Booth's handles signed multiplication directly by encoding runs of 1s as (shift + subtract) instead of multiple adds. More efficient in hardware.
5. **"Why iterate on the smaller operand?"** → Fewer set bits = fewer additions. If you can swap so the smaller value is the multiplier, you skip more zero-bit iterations (optimization for early termination).
